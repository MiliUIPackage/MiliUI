# 米利的滑鼠提示 MiliUI_Tooltip

12.1 起的自製滑鼠提示。單位、光環、巨集提示走「就地改寫」（在暴雪 tooltip 底下墊自己的 skin 框、
post-call 加行改色）；物品與法術提示另外走「重繪面板」。

taint 接觸面清單在 `Core/Hooks.lua` 檔頭，**要碰暴雪物件的新程式碼必須先過那張表**。

## 重繪面板（`Panel/`）

物品、法術提示：原生 tooltip 留在底下當替身，旁邊畫一個自己的 panel 自由排版。
設定在「物品與法術」分頁最上面的「面板」（物品、法術各一個開關，預設開）。

### 做法

- **原生 tooltip 不藏、只看不見**：`SetAlpha(0)`，`SetPadding` 撐到跟 panel 一樣大。
  暴雪的比價框定位、螢幕邊夾邊、跟隨游標全部照原生框的尺寸算，原生撐大之後那些系統自然把兩者當成一個框，
  定位一行都不用重寫。
- **panel 是自己的框**（parent `UIParent`、strata `TOOLTIP`、層級 = tooltip + 5；預覽時 parent 是設定視窗、
  不另設 strata）。照 tooltip 被錨的那一側貼齊上緣，角落修到整數像素。
- **入口只有既有的 post-call**（`Core/Hooks.lua` 的 `OnItem`／`OnSpell`），在 `Item.Apply`／`Spell.Apply`
  之後呼叫 `Panel.Try`：我們自己加的 ID 行、別的插件 `AddLine` 加的行都已經在 tooltip 上了。
- **讀行**（`Panel.CollectLines`）：`data.lines` 逐行讀型別、左右欄、顏色；`lineIndex` 不在 data 裡的
  `TextLeftN`／`TextRightN` 全部撿回來放「其他」區，顏色照它自己的。一行都不能丟。
- **語系**：認行用的 pattern 全部從 `_G` 的 GlobalStrings 反轉產生（`Panel/Patterns.lua`），不寫任何語言的字面。
- **效能**：重畫前比指紋（所有行文字＋顏色＋設定版本），比價框每秒重建二十幾次時只重壓 alpha、不重畫；
  FontString／Texture 用池只增不刪；沒有 OnUpdate，跟著 tooltip 的共用輪詢（`Skin.Poll`，0.1 秒）走。
- **內容被清掉**（`OnTooltipCleared`）先不拆、下一幀還沒被新內容認領才拆；tooltip 藏起來（skin `OnHide`）立刻拆。
- **抖動的根本規則**（`Panel/Try.lua`）：同一次停留裡提示內容本來就會變好幾次（背包格每 0.2 秒重設、法術資料晚到、
  別家插件的行輪流出現；實機記錄同一件記到三種行集合），所以幾何與重畫都照規則走，不追個案：
  - 同一件（型別＋id）的 **panel 寬度只長不縮**、**原生替身的高度只長不縮**（換一件歸零）；
  - 行數**變多**立刻重畫（補齊）；行數**變少**、或**行數不變但內容變了**，都要連續 0.3 秒才採用——輪流出現的版本永遠採用不到，面板停在第一個完整版；
  - 設定改了例外，直接重畫。
- **同一件的重建不立刻重畫**（`Panel/Try.lua`）：post-call 在暴雪 `ProcessInfo` 的中間，比價框的「若你更換此裝備…」、
  別家插件 post-call 加的行都是同一幀、我們之後才補上。同一件（型別＋id）只重壓 alpha、撐 padding，排一次下一幀的 Reconcile，
  到時候行已經補齊才比指紋、需要時重畫。行數比這件看過的最多還少＝部分版，不准蓋掉完整版；連續 0.3 秒都比較少才接受
  （修飾鍵放開、冷卻行消失）。新的一件照樣當幀就畫（第一次顯示最多閃一次）。
- **行頭／行尾的單顆行內圖示**（`|T…|t`、`|A…|a`）拆出來另外貼一張貼圖、垂直置中在那一列，不靠 FontString 的行內排版
  （實機：附魔行尾的品質圖示掉半行）。一串裡有兩顆以上（錢幣）就不拆，免得跟其他幾顆對不齊。
- **鏡射錨點**：原生錨在另一顆已接管、面板顯示中的 tooltip 上（比價框錨在主提示、ShoppingTooltip2 錨在 1），
  面板照原生的每一個點把對象換成對方的**面板**（點與位移原樣）。主提示的自然寬高每次重設都會短暫變一下，
  比價框的原生跟著動；鏡射之後比價面板只依賴主面板，主面板的穩定就傳下去。主面板退回時，鏡射在它身上的面板當場改回貼自己的原生。
- **原生不夾邊、面板自己夾**：接管期間原生 `SetClampedToScreen(false)`（退回時寫回原值），面板本來就夾在螢幕內，
  夾邊範圍把附屬框（底下）與「已裝備」標籤（上方）算進去，四邊再多留一圈呼吸（`LOOK.EDGE_MARGIN`），貼在螢幕邊時 1px 邊框不會被頂掉。
  暴雪的夾邊照原生總高決定要不要往下推，原生高度一抖就整組跳。
  **鏡射在別的面板上的面板自己不夾**（位置完全由目標決定，自己再夾會跟目標拆開），由鏈的根（主面板）替它預留標籤高與附屬框高；
  所以比價時三顆身體的上緣對齊，標籤露在上方。
- **貼原生被錨定的那一角**：原生從下緣錨定（跟隨游標、固定右下）就貼下緣，從上緣錨定（比價框）就貼上緣；
  有附屬框時原生的底是整組的底。暴雪重設提示時 padding 會被清掉一幀、原生暫時變矮，被錨定的那一邊不動，panel 就不跳。
  padding 被清掉時當幀（含 Show 後掛勾）直接補回上次的值，不拿那一幀不可信的高度重算。診斷：`/mtip panel`。
- **原生沒有點時不改錨**：比價框重建時暴雪先清掉原生的點、之後才重貼；這一刻面板沿用上次的錨點，不退到暫時位置。
  同一角、原生位置移動不到半個像素時沿用上次的取整位移，不在四捨五入的邊界上 1px 來回跳。
  原生自己的自然寬高同一件也只長不縮：暴雪推開主提示的距離用比價框原生的寬算，寬一變整條鏈就動。
- **比價標籤照抄暴雪的字**：原生比價框上方的「已裝備」／「同時裝備」標籤文字原樣搬到面板上；讀不到就用「已裝備」，原生沒有標籤就不畫。
- **附屬框**（設定「其他插件的補充行另開一框」，預設開）：別的插件後加的行（含我們自己的資料片／ID 行）另開一框接在主面板下面，
  寬同主面板、底色同主面板、邊框用基底邊色（不吃品質色）。原生框撐到「主面板＋縫＋附屬框」，比價框與夾邊照整組算。
  暴雪 data 裡認不出的行仍留在主面板的「其他」區。
- **重複的售價行**（設定「隱藏其他插件重複的售價行」，預設開）：頁尾已經畫了售價時，附屬框裡金額跟售價相等的行不顯示
  （別家的「售價: 38 75 34」、「商人 x1 …」）。只比金額不看標籤字：數字後面有金／銀／銅幣圖示就照幣別加總比，只有部分數字帶圖示才比非零的金／銀／銅段；**一個幣別圖示都沒有的行一律不藏**（售價 1 銅時「總計：1」「背包：1」不能被當成售價）；
  堆疊數「x1」先剝掉。總價與單價（見下一條）都認；x3 這類別家算的總價跟兩者都不同，不會被藏。暴雪 data 的行不動。
- **堆疊物品的售價**：暴雪給的售價是整疊的。數量大於 1 時頁尾畫「單價 ×數量 = 總價」（例：「30銀 ×2 = 60銀」）；
  單價來自物品資訊的售價，數量先問這一格的堆疊數，問不到才用總價除以單價（要整除）。單價拿不到或數量 1 就只畫總價。

外觀：提示皮（底 `general.background` 不透明、1 實體像素的邊、白字、直角，不鋪紋理不漸層）；
邊框色跟就地改寫那套同一組（品質色），分隔線白 alpha 0.22，◆ 用玩家職業色。數值集中在 `Panel/Frame.lua` 的 `Panel.LOOK`。

- **基底邊色**（設定「邊框預設用職業色」，預設開）：沒有內容色的框（法術面板、附屬框、套組交給我們的框、單位提示還沒上色前）邊是玩家職業色（HUD 皮的 1px 職業色邊）；
  物品品質色、單位的職業／立場色照樣蓋過去；關掉用「邊框顏色」選的那個色。來源 `Panel.BaseBorderColor`，`Skin.ResetColors` 也走它。
- **框與框之間留縫**（`LOOK.FRAME_GAP = 6`）：附屬框與主面板、比價面板之間、貼在面板旁的別家框（外觀預覽）。
  鏡射改貼面板時，點對是相鄰邊（右貼左、底貼頂…）就往外推一個縫；同邊對齊（頂貼頂）不動。原生框照暴雪的緊貼。
- **貼在面板旁的別家框**（外觀預覽，經 `Adopt` 的 `followPanel`）：它自己選的點不算數——它是照**原生**的幾何決定貼哪一邊的，
  而接管期間原生不夾邊、又被撐到跟面板一樣大，會超出螢幕，那個判斷會亂（每 0.2 秒換邊、選到「上方」時整個框在螢幕外）。
  改由我們定位：貼整條面板鏈（主面板＋比價面板）最外側那顆的外側、上緣對齊主面板、留一個縫；
  第一次選邊照它的偏好（它的點讀得出想貼左或右；它有「往螢幕中央靠」「避開比價框」的設定），那邊放得下就照它的；
  換邊有遲滯（這一邊放得下就不換，另一邊要多出 `LOOK.FOLLOW_HYST = 24` 的餘裕、離上次換邊至少 `FOLLOW_DWELL = 0.3` 秒才換；
  兩邊都放不下選比較寬的）；跟隨期間把它夾在螢幕內。面板鏈每次對齊也重算一次，比價面板出現時當幀跟上。
  幾何讀不到的那一輪沿用上一次的貼法、下一幀再算，**不退回它的點**（退回會這幀它的、下幀我們的＝左右閃，實機第二輪抓到）。
  貼著的比價面板退了、主面板還在 ⇒ **交棒**：用同一個螢幕位置改貼到主面板、一個像素都不動，0.3 秒保留期內不往內縮；
  比價面板回來就貼回去（位置一樣）。比價框每 0.2 秒重建時那顆面板下一幀就回來，當場重算會先縮到主面板邊緣再貼回去＝抖（實機第三輪）。
  主面板退了（拍賣場刷新列表時 GameTooltip 先 Hide 再 Show，面板拆掉重畫）⇒ **停在原地**：改貼 UIParent 的同一個螢幕位置、夾邊不還，
  面板回來就重新跟上；它自己 tick 進來、對象暫時沒面板也維持停著；超過 0.3 秒都沒回來才真的還給它。以前這時立刻還給它＝貼回
  超出螢幕的原生旁邊、它下一個 0.2 秒才又跟上＝每次刷新上下跳一大截（實機第四輪：兩份 dump 一份沒在跟、一份剛掛勾）。
  `/mtip panel` 多印一行「跟隨框」：我們選的邊、實際貼在哪、它原本要貼哪、幾何讀不到幾次與原因、交棒幾次；
  `/mtip panel watch` 也取樣跟隨框的位置、貼在哪一顆、哪一側。

### 失敗方向：退回現有樣式

下面任何一項成立，就**不藏原生、不顯示 panel**，現有的 skin 管線（品質邊框、ID 行、名稱前圖示）照常：

- 任何一行的文字、型別、顏色、`lineIndex` 是秘密值；別人後加的行讀到秘密值
- tooltip 的 `GetPoint`／`GetLeft`／`GetTop`／`GetWidth`／`GetPadding` 任何一個回秘密值
- 讀不出名字、render 出錯（`Core/Hooks.lua` 的 xpcall 接住後 `Panel.Fail` 退回）
- 內嵌物品框（世界任務獎勵）或底部說明字顯示中——那時暴雪自己在用 padding

**開關關掉時對 tooltip 零寫入**，畫面跟沒有這個功能時完全一樣。

### 接觸面（`Core/Hooks.lua` 檔頭 #10～#13）

- #10 `tip:SetAlpha(0)`／還原、`tip:SetPadding(right, bottom, left, top)`／還原。只在 panel 成功顯示時寫；
  padding 只在「tooltip 還顯示著、而且還是我們設的那個值」時寫回（暴雪的 `OnShow`／`OnHide` 會自己 `ClearPadding`）；
  alpha 只在還是 0 時寫回。
- #11 `ItemRefCloseButton` 的 `ClearAllPoints`／`SetPoint`：聊天連結提示的 panel 畫一顆 ×（純畫、不收滑鼠），
  把原生關閉鈕（跟著原生框 alpha 0，看不見但點得到）疊上去，點擊走原生按鈕自己的安全路徑；退回時貼回原位。
  **不從我們的程式 `Click()` 它**：它的 OnClick 是 `HideUIPanel(ItemRefTooltip)`，在污染的執行裡跑會連坐面板管理與比價管理器的共用狀態。
- #13 `tip:SetClampedToScreen(false)`／還原：接管期間原生不夾邊，改由面板自己夾。
- #12 `hooksecurefunc(tip, "Show")`／`(tip, "SetShown")`：暴雪的 Show 會把 alpha 改回 1、而且在 post-call 之後才叫，
  後掛勾同一幀壓回 0。只掛在真的用過面板的 tooltip 上，面板沒在用時掛勾什麼都不做。
- 暴雪物件上零欄位寫入，per-tip 狀態在 `Skin.State[tip]`（`state.panel`、`state.native`…）。

### 法術（`Panel/ReadSpell.lua`、`ViewSpell.lua`）

- 標題：圖示、名字、徽章列（被動｜天賦等級｜副標｜最大充能）。
- 四格（設定「法術四格」）：耗能／施法／冷卻（有充能時是「恢復」）／距離，固定順序；缺的格顯示含義
  （無／立即施法／無／自身）並用暗灰。時間用 GlobalStrings 的短格式（「冷卻時間8秒」→「8秒」）。耗能值用資源色亮化。
  關掉時照原生的兩欄排。
- 描述**整段畫、不切句**（中文沒有「句點＋大寫」可切），`|n` 照留；描述裡的數字上色（職業色亮化／自訂／不上色）。
  **只上色、不加粗**：FontString 不能局部換字型。
- 需求（未達成紅）、剩餘冷卻（橘）、材料／工具、天賦面板的「下一級」（Caption）、巢狀法術（變形後的版本：小一號標題＋同一套）。
- 天賦面板的名字與等級是寫在 data 之外的後加行：畫在第 1 行的那一行當名字。

### 物品與配方（`Panel/ReadItem.lua`、`ViewItem.lua`）

- 標題：圖示＋物品等級徽章（設定「圖示下顯示物品等級」）；名字（品質色）、「護甲類 · 部位」、「綁定 · 唯一 · 需要等級 · 技能需求」（未達成紅）、提升等級／製造品質。
- ◆ 分隔：武器（大字每秒傷害＋小字「傷害 · 速度」）／護甲（大字）、屬性（◆ 職業色，主 1.0／次 0.85／三 0.7，三類之間細線；不適用的灰字照灰）。
- ◆ 分隔：效果（小標籤＋綠字）、需求、插槽、附魔、冷卻與其他細節、套裝（名字金、物件未擁有灰、加成未啟用灰）、風味文字（金）。
- **配方（推定，待實機）**：第二個物品名字（或物品型的巢狀區塊）之後是成品，畫在 Caption「製造」底下（小圖示＋名字＋一行灰字＋屬性）；
  「材料：」那一行（或它之後到空行為止的行）畫在 Caption「材料」底下，右欄「擁有 / 需要」、不足紅。
- 頁尾帶：職業／種族／聲望／專精限定（靠右、未達成紅）、耐久條（MiliUI Satin、職業色）＋「120 / 165」、售價。
- 比價框：左上方外側的標籤，字照抄原生比價框的（「已裝備」／「同時裝備」）。
- 實機資料（`Tests/fixtures/real_zhTW.lua`）對出來的規則：名字之後、綁定／部位之前的無型別行是**標題補充行**
  （難度、虛無鍛造、已塑形為…，原字串原色照 `\n` 拆列，暴雪的壞色碼「|cFF 0FF 0」照樣容忍）；`DisabledLine` 看情境
  （套裝清單裡＝沒擁有的那件、屬性＝同職業其他專精的主屬性畫灰、其餘＝灰字細節，不再當成紅字需求）；盾牌格擋寫在護甲的第二行；
  臨時附魔（武器油）跟在附魔之後；「按下 Shift+右鍵以插入寶石」進細節；售價那行的文字是空的（要在「空行＝分段」之前認走）。
- 配方、被動、天賦、充能法術目前**沒有實機資料**，那幾段仍是推定。

認不得的行一律進「其他」區（不許少行）。最簡 reader（`ReadFallback.lua`）留著當「型別不認得」的退路。

## 記錄模式（`/mtip record`）

reader 要照真實的行結構寫，這個指令把遊戲裡實際的提示資料記下來：

- `/mtip record on` 之後每次滑過物品／法術都自動記一筆；`/mtip record off` 停；`/mtip record clear` 清空；
  `/mtip record` 印目前筆數與開關。
- 每筆：`data` 整張結構＋當下所有行的文字與顏色＋語系＋tooltip 名字，秘密值標 `"<secret>"`。
- 同一個 id＋型別＋行數只留一筆；上限 60 筆。
- 存在 `MiliUI_Tooltip_DB.dumps`（帳號層級）。**SavedVariables 只在 `/reload` 或登出時才寫進檔案。**
  開關也存帳號層，`/reload` 後還開著，登入時聊天會提醒。

```bash
for f in AddOns/MiliUI_Tooltip/Tests/*_test.lua; do lua "$f"; done
```

`Tests/helpers.lua` 是共用的假框、假環境與秘密值哨兵（比較、算術、串接一碰就 error ⇒ 測試沒炸就證明只傳不讀）。
三語的 GlobalStrings 實值抄自 `Interface/tmp/GlobalStrings/gs_{enUS,zhTW,zhCN}.csv`：reader 測試共用的那份在
`Tests/fixtures/GlobalStrings.lua`（從 CSV 挑 key 產生、不要手改）。法術／物品 fixture 是用這些格式字串 format 出來的手拼行，
真實行佈局的 fixture 是 `Tests/fixtures/real_zhTW.lua`（2026-10-18 的 `/mtip record` 記錄，17 筆），由 `Tests/tools/export_real_fixture.lua` 從 SavedVariables 轉出，**別家插件後加行裡的角色名／伺服器／公會名會自動換成假名**（repo 公開）。要補新記錄就重跑那支工具，不要手改 fixture。
