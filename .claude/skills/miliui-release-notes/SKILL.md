# MiliUI 更新資訊

指令長這樣：**`{目標} 更新資訊`**

目標是套組發佈日（`825`、`20260825`）或某個插件加版本（`MiliUI_UnitFrames 1.2`）。
沒指定版本就抓最新的那個 tag。

產出是**給玩家看的**，不是 changelog。git log 已經是 changelog 了，再抄一份沒有價值。
玩家不在乎為什麼壞掉，只在乎「我會看到什麼不一樣」跟「開關在哪」。

---

## 1. 決定版本區間

tag 慣例：

| 目標 | tag 格式 | 例 |
|---|---|---|
| 套組本體 | `YYYYMMDD`（同日第二次加 `-2`；2024 的舊 tag 有 `v` 前綴） | `20260825` |
| 自製插件 | `<插件名>-<版本>`，**大小寫跟資料夾不一樣**（`Miliui_` 對 `MiliUI_`） | `Miliui_UnitFrames-1.2.0` |
| 第三方 fork | `<插件>-<上游版本>_MiliUI` | `Cell-r295_MiliUI` |

```bash
git for-each-ref --sort=-creatordate --format='%(refname:short)  %(creatordate:short)' refs/tags | head -20
```

- **依建立時間排序，不要用字串排序** —— 日期 tag 與插件 tag 交錯在同一條時間軸上。
- tag 是 annotated，要拿 commit 用 `git rev-list -n1 <tag>`。
- 區間＝**上一個同類 tag（不含）到目標 tag**。套組只跟套組比，插件只跟自己比。
- 目標還沒 tag（剛 bump 完版本號還沒打 tag）→ 用 HEAD，交件時說一聲範圍算到哪。
- 一個插件的 tag 常常晚一步：版本號 bump 的 commit 可能落在上一個套組發佈之前，
  代表那些內容玩家已經拿到了。照 tag 區間走就對，不用補回去。

## 2. 撈材料

```bash
git log --format='=== %h %s%n%b' <prev>..<curr> -- <路徑>
```

- 套組本體：路徑留空（整包都算，包含第三方插件的更新）
- 個別插件：`-- AddOns/MiliUI_UnitFrames`

**一定要讀 body，不能只看 subject。** subject 常常只寫症狀或內部代號，
body 才有「玩家實際會看到什麼」「設定在哪一頁」「預設開還是關」。

## 3. 篩掉不該出現的

- **同一區間內被推翻的中間過程。** A commit 加了功能、B commit 又把它換掉 ——
  玩家從沒拿到 A，只寫 B 的最終樣子。
- **自產自修的 bug 不是修正。** 這一版才寫進去、同一版修好的，對玩家而言不存在。
- 版本號 bump、註解整理、`.claude/` 的筆記與技能。
- 內部重構、資料庫遷移、快取、taint、秘密值 —— 除非玩家看得到差別
  （變順了、不再卡頓、不再崩潰）。
- 不要寫「參考了哪個別的 UI 套組」。套組**內含**的插件名（MRT、HandyNotes、Cell…）
  照寫，玩家要靠名字認出那是哪個功能。

## 4. 分類與寫法

三段就夠：**新增 / 修正 / 調整**。沒有的段落直接不要，不要留空標題。
效能改善併進「調整」，而且要翻成玩家的感受（「切分頁比較不會頓」）。

每條一句話：

- **新增** → 這功能做什麼 ＋ **設定路徑** ＋ 預設開還是關
  設定路徑照介面實際的層級寫：「單位 → 血條 → 顏色 → 閾值上色」。玩家要找得到。
- **修正** → 寫**症狀**不寫根因，句型是「以前 X，現在 Y」
- **調整** → 改了什麼、誰會注意到

不要出現：API 名、函式名、檔名、資料庫版本、commit hash、「秘密值」「taint」「遷移」。
數字只在對玩家有意義時才寫（「門檻最多 6 個」要，「圖示 17 改 24」寫成「跟目標框一致」）。

## 5. 三語

繁中先定稿，另外兩份照它翻，不要各自發揮 —— 三份的條目要一條對一條。

用語對照（台服 / 國服 / 官方英文）：

| 繁中 | 簡中 | English |
|---|---|---|
| 魔力 | 法力 | Mana |
| 名條 | 姓名板 | nameplate |
| M+ | 大秘境 | Mythic+ |
| 副本 | 副本 | dungeon |
| 團隊 | 团队 | raid |
| 探究 | 地下堡 | Delve |
| 光環（增益／減益） | 光环（增益／减益） | auras (buffs / debuffs) |
| 閾值上色 | 阈值上色 | Threshold coloring |
| 施法條 | 施法条 | cast bar |
| 頭像 | 头像 | portrait |
| 資源條 | 资源条 | class resource |
| 血條 | 血条 | health bar |
| 職業色 | 职业色 | class color |
| 首領框 | 首领框 | boss frames |
| 焦點 | 焦点 | focus |
| 分身 | 小号 | alts |
| 巨集 | 宏 | macro |
| 標記 | 标记 | raid marker |
| 滑鼠提示 | 鼠标提示 | tooltip |
| 分頁 | 标签页 | tab |
| 設定 | 设置 | settings |
| 拾取專精 | 拾取专精 | loot spec |
| 快捷聊天列 | 快捷聊天栏 | chat bar |
| 儲物箱 / 寶庫 | 储物箱 / 宝库 | Stash / Great Vault |

- **簡中不是繁轉簡**，用語要換（魔力→法力、探究→地下堡）。
- 英文用暴雪官方詞，不要自創。
- **設定路徑三語都要換成該語系介面實際顯示的字**：去 `AddOns/<插件>/Locales/zhCN.lua`
  查對應的翻譯，不要自己翻。英文直接用 L 的 key —— 那套語系表的 key 就是英文原文
  （`Locales/Locale.lua`），所以沒有 enUS.lua。

## 6. 交件

三份用標題分開，直接貼在回覆裡，不必存檔（使用者要才存）。
最後補一行實際採用的 tag 區間（`Miliui_UnitFrames-1.1.6 → 1.2.0`），
讓使用者一眼看出範圍對不對、要不要改。

## 檢查清單

1. 區間是同類 tag 相比，不是拿插件 tag 對日期 tag
2. 讀過每個 commit 的 body，不是只看標題
3. 區間內被推翻的功能、自產自修的 bug 都拿掉了
4. 每條新增都有設定路徑與預設值
5. 修正條寫的是症狀，不是根因
6. 沒有 API 名、檔名、hash、內部術語
7. 三份條目一條對一條，簡中換過用語、英文是官方詞
8. 設定路徑查過各語系檔，不是自己翻的
