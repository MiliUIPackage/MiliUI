# MiliUI 選單設計標準

從 `MiliUI_DamageMeters/Meter/Menu.lua` 的實作與使用者回饋蒸餾出來的。
**新做任何選單之前先讀完，交件之前照最後那份檢查清單走一遍。**

參考實作：[`AddOns/MiliUI_DamageMeters/Meter/Menu.lua`](../../../AddOns/MiliUI_DamageMeters/Meter/Menu.lua)

---

## 一、最重要的一條：一個視覺訊號只能有一個語意

**這是最容易犯、也最難自己看出來的錯。**

實際踩到的：選單裡「標題」與「目前選中的項目」都上了強調色，結果子選單最上面兩行
（標題「統計類型」、選中的「傷害輸出」）長得一模一樣，使用者分不出哪個是標籤哪個是選項。

修法不是「把其中一個換個顏色」，而是讓兩者**往相反方向走**：

| | 語意 | 該長什麼樣 |
|---|---|---|
| 標題 | 後設資訊，不可點 | **比內容更弱**：灰、字級 −1、底下一條髮絲線 |
| 已選 | 內容，而且是當前狀態 | **比內容更強**：強調色 ＋ 左槽打勾 |

寫任何新的視覺狀態之前先問：**這個顏色／字重／圖示，在這個畫面裡已經代表別的意思了嗎？**

## 二、階層要靠三層訊號，不能只靠顏色

顏色是最弱的一層 —— 色盲玩家、低對比螢幕、遊戲背景亂七八糟的時候它就失效了。
每個重要狀態至少要有兩層：

1. **顏色** — 最快被看到，但最不可靠
2. **結構** — 分隔線、留白、縮排、字級。這層最穩，也最常被忘記
3. **圖示** — 打勾、箭頭。語意最明確

「標題／選中」之所以修得好，不是因為換了顏色，是因為加了**分隔線**（結構）與**打勾**（圖示）。

## 三、狀態用打勾，而且不要畫框

- 整列本來就可點的選單，**勾選框的框是多餘的噪音**。只畫勾。
- **中文字型沒有 `✓`**，用字元會變方框 → 一定要用材質。
  暴雪的 `checkmark-minimal` 圖集是首選（跟 `MiliUIWidgets` 的勾選框同一個素材）。
- ⚠ **圖集當貼圖直接染色會偏暗** —— 染色是乘法，而素材不是純白。
  正解：純白貼圖染色，**勾形用圖集的 alpha 當遮罩**摳出來。
- ⚠ **atlas 被暴雪拿掉是靜默失效**（見 [miliui-inspect-icons](../miliui-inspect-icons/SKILL.md)）。
  一定要留退路 —— `Interface\Buttons\UI-CheckBox-Check` 從古至今都在，而且那張本來就只有勾沒有框。
- `>` 這種箭頭用字元可以（ASCII，中文字型有）。

## 四、留固定的圖示欄（gutter），每一列都要留

**只在「有勾」的那列才留位置的話，文字會參差不齊 —— 這是業餘感最明顯的破綻。**

```
PAD_X   面板左右內距        6
GUTTER  打勾欄寬（固定）    16
文字起點 = PAD_X + GUTTER
```

沒勾的列 gutter 空著，文字照樣對齊在同一條線上。

## 五、不要讓人「點開才知道自己選了什麼」

階層式選單最常見的不直覺來源。父列右側直接顯示目前的值：

```
統計類型          傷害輸出  ›
分段              本場      ›
```

- 值用**灰**，不用強調色 —— 它是**狀態讀數**，不是「這一列被選中了」。
  上強調色會跟子選單裡真正的選中項搶同一個語意（回到第一條）。
- 寬度計算要把值算進去：`PAD_X + GUTTER + 標籤寬 + VAL_GAP + 值寬 + 箭頭寬 + PAD_X`。

## 六、互動也是 UX

- **子選單的關閉要有寬限期。** 從父列斜著移向右邊的子選單，路徑一定會經過主選單的
  其他列。那些列的 `OnEnter` 若**立刻**關掉子選單，體感就是「滑鼠稍微移過去就關了」，
  根本點不到。做法：非子選單列只**排程**關閉（0.4 秒），到期時再判斷游標在不在子選單裡
  —— 判斷點放在**到期時**而不是排程時，中途繞進去也算數。用世代 token 讓舊排程作廢。
- **子選單與父面板之間不要留縫。** 差 1px 游標就會掉進「兩個選單中間」，路徑就斷了。
- **開關型項目按下去要原地重畫**（更新勾選狀態），不是關掉重開。
  ⚠ 直接再呼叫 `Show` 會撞上「同一顆再按一次＝關閉」的 toggle 判斷 —— 要有 `keepAnchor`
  之類的參數，而且要記住上次解出來的錨點（游標錨定的選單否則會跳位）。
- **游標會蓋住東西。** 游標圖形是從熱點往**右下**延伸、約 32px 見方，比按鈕還寬。
  工具提示放「按鈕正下方置中」還是會被蓋掉右側幾個字；要嘛放正上方，
  要嘛整個退到按鈕**左緣以外**。細節見 [[project-miliui-damagemeters]]。

## 七、文案

- 標籤講**結果**不講機制：「這個視窗不磁吸」>「停用磁吸」。
- 破壞性動作（重置、刪除）跟一般項目之間要有分隔線，而且**不要放在第一個**。
- 只是化妝的功能要講清楚代價，不要讓玩家以為省到了資源。

## 交件前的檢查清單

- [ ] 有沒有兩個東西共用同一個視覺訊號（顏色／字重／圖示）？
- [ ] 標題是不是**比**選項弱（灰、小一級、有分隔線）？
- [ ] 已選的項目有沒有**顏色以外**的第二個訊號（打勾）？
- [ ] 打勾欄是不是每一列都留，文字全部對齊在同一條線上？
- [ ] 勾是材質不是 `✓` 字元？atlas 有沒有退路？
- [ ] 有子選單的父列有沒有顯示目前值？值是灰的嗎？
- [ ] 寬度計算把打勾欄、值、箭頭都算進去了嗎？
- [ ] 斜著移向子選單會不會半路被關掉？
- [ ] 開關項目按下去是原地重畫，還是整個選單關掉？
- [ ] 破壞性動作有沒有跟一般項目分開？
- [ ] 拿去 3 倍放大截圖看一眼 —— 小尺寸下糊掉的東西在原尺寸看不出來。

## 驗證手法

不用進遊戲也能先看出七成問題：**用 Pillow 把選單照實際尺寸畫出來、放大 3 倍並排比對**
（BEFORE / AFTER）。這次「標題與選中混淆」就是這樣一眼確認修好的。
一次性的比對腳本寫在 scratchpad 就好，不要留進 repo。
