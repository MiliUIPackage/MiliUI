# MiliUI 狀態上色標準

一句話：**狀態不換色，只換色調。**

顏色負責「這是誰」，明暗負責「它現在怎麼了」。兩件事各自有專屬的視覺通道，
不互相搶，畫面就會乾淨。

參考實作：[`AddOns/MiliUI/Enhance/Chattynator_TabStyle.lua`](../../../AddOns/MiliUI/Enhance/Chattynator_TabStyle.lua)

---

## 這套手法的正式名字

沒有一個單一的名字，它是三個標準做法疊起來的。要跟人解釋的時候這樣講：

| 手法 | 業界術語 | 這裡怎麼用 |
|---|---|---|
| 一個來源色推導出整組 | Material 3 的 **seed color → tonal palette** | 玩家設的標籤色是 seed，三態全部算出來 |
| 狀態靠同一疊層的不同強度 | Material 3 的 **state layer** | 選中／滑過／閒置＝同一條公式的三個係數 |
| 混色而不是疊透明 | **tint / shade**（相對於 alpha compositing） | 往深底混出不透明的純色 |

再加一條沒有專有名詞、但實際上最關鍵的：**色相恆定（hue-preserving）**——
三態的色相完全一樣，只有明度在動。

## 公式

```lua
-- 把來源色往深底混，得到不透明的純色
local BASE = 0.07
local rest = BASE * (1 - k)
r, g, b = seedR * k + rest, seedG * k + rest, seedB * k + rest
```

就是 `mix(深底, 來源色, k)`。k 是唯一的旋鈕。

| 狀態 | k（底色） | 邊框 alpha | 整體 alpha |
|---|---|---|---|
| 選中 | 0.55 | 1 | 1 |
| 滑過 | 0.28 | 0.85 | 0.85 |
| 閒置 | 0.12 | 0.55 | 0.85 |

實測過的值，要調就整組一起調，不要只動一個 —— 階梯的**間距**才是被看見的東西。

## 一、來源色只有一個，其他全部算出來

**最容易犯的錯是替每個狀態各挑一個顏色。** 挑三次就會有三種色相飄移，
放大到五六個元件（一排標籤、一排按鈕）就變成一團雜訊 —— 這正是內建 skin 的標籤
看起來很亂的原因。

只要能寫成 seed + 係數，就永遠不會飄。而且好處是**外部給什麼色都吃得下**：
玩家自訂色、職業色、品質色、陣營色，同一條公式全部長得像同一套 UI。

## 二、底色壓暗，邊框保飽和

分工要明確：

- **底色**是大面積，壓到很暗（k ≤ 0.55）—— 大面積的飽和色會蓋掉上面的文字，
  也會跟旁邊的元件互相打架。
- **邊框**是細線，維持原色不打折（只調 alpha）—— 細線再飽和也不刺眼，
  而且這是玩家一眼認出「這是哪一個」的地方。

顏色資訊集中在 1px 的邊上，畫面就會同時「有顏色」跟「安靜」。

## 三、底色要不透明

⚠ **不要用 alpha 疊在背景上。** 遊戲背景是會動的（跑過草地、進副本、開地圖），
半透明底色的觀感會跟著背景一起飄，同一個標籤在不同場景看起來是不同顏色。

混色算出來的不透明純色到哪裡都一樣。這也是 `SetColorTexture(r, g, b, 1)` 而不是
`SetColorTexture(r, g, b, 0.5)` 的理由。

（邊框可以用 alpha —— 它是細線，飄一點看不出來，而且省一次混色。）

## 四、往深底混，不要往純黑混

`BASE = 0.07` 不是隨便挑的：

- 混到 **0（純黑）**，深色系的來源色（深綠、暗藍）在閒置態會直接消失成黑塊，
  玩家看不出那裡有個可以點的東西。
- 0.07 比套組面板底（`MiliUI.Style.Dark.panel` = 0.1）再暗一階，
  所以元件仍然「沉在」面板裡，但摸得到邊。

同一個理由在 `Widgets.lua` 也出現過（勾選框底色特意比其他控件亮一階，
因為它是唯一「沒勾就什麼都沒有」的控件）。

## 五、文字統一白，不要跟著來源色跑

彩色底上放彩色字＝兩個弱訊號互相抵銷。**文字一律白，靠底色與邊框表達身分。**

三個標籤的字色各不相同，是「看起來很雜」的另一半原因。

⚠ 換字色如果要動字型物件，**file / size / flags 一定要原樣沿用、只改顏色**。
換成不同字級會讓 FontString 重新配置並吃掉最後一個字（`Widgets.lua` 踩過），
而且宿主插件常常是量字寬來算元件寬度的，換了會跑版。
有的 skin 是直接對 FontString `SetTextColor`，那會蓋過字型物件 —— 兩邊都要補。

## 六、什麼時候**不要**用這套

這套是給「元件本身帶身分色」的情況。元件沒有自己的顏色時，
走 [`Libs/MiliUIWidgets/Widgets.lua`](../../../AddOns/MiliUI/Libs/MiliUIWidgets/Widgets.lua)
既有的那套：`WIDGET_FILL` 底 ＋ hover 換職業色邊框（`BTN_COLORS`）。

判準很簡單：**這個元件的顏色是誰決定的？**

| 顏色來源 | 用哪套 |
|---|---|
| 玩家設定／職業／品質／頻道 | 本文這套（seed 推導） |
| 我們自己決定 | `Widgets.lua` 的 `BTN_COLORS` |

兩套並存不衝突 —— 明暗階梯本來就一致（0.115 / 0.23 對上 k = 0.12 / 0.28）。

## 形狀的部分

上色以外，套組樣式的其他固定件：

- **直角**。不要圓角。
- **邊框 1px**，而且一定要走 `P.Scale(1)`（`ns.P`），不要寫死 `1`
  —— 否則不同 UI 縮放下邊會忽粗忽細，見 [[project-miliui-pixel-snapping]]。
- **白貼圖**：`Interface\Buttons\WHITE8X8`。
- 分頁／標籤這種「跟下方內容連成一片」的東西，**底邊那條不要畫**（只畫上左右三條）。

## 交件前的檢查清單

1. 三態的顏色是不是**都從同一個 seed 算出來的**？有沒有哪一態是手挑的？
2. 底色是**不透明**的嗎？（背景換場景會不會飄？）
3. 邊框有沒有維持原色的飽和度？顏色資訊有沒有集中在邊上？
4. 最暗的那一態，**深色系的來源色**還看得出來嗎？（拿深綠、暗藍試）
5. 文字是不是統一白色？有沒有殘留宿主原本的彩色字？
6. 邊框走 `P.Scale(1)` 了嗎？圓角清乾淨了嗎？
7. 元件如果**沒有**身分色，是不是誤用了這套而不是 `Widgets.lua` 那套？
