# 蒸餾最近的工作

把 git 歷史裡的**經驗**撈出來，寫成下次會派上用場的東西。

這不是產生變更日誌。git log 本身就是變更日誌了，再抄一份沒有價值。目標是找出
**「知道就省半小時、不知道就重踩一次」**的東西。

## 步驟

### 1. 取材

```bash
git log --since="<起始日>" --pretty="%h %ad %s" --date=short
git log --since="<起始日>" --name-only --pretty=format: | awk -F/ '/^AddOns\//{print $2}' | sort | uniq -c | sort -rn
```

沒指定日期就問使用者，或用上次蒸餾的時間點（看 `.claude/notes/` 檔案的 git 修改時間）。
先看分組結果決定深入哪幾個 —— 動最多的那幾個插件通常就是故事所在。

`fix:` 的 commit 比 `update:` 有價值得多：前者是踩到坑，後者多半只是同步上游。
單獨看一下 `remove:` —— 試過然後放棄的東西，理由往往沒有人記下來。

### 2. 篩選（最重要的一步）

**只有同時滿足這兩個條件才值得寫下來：**

- **會再遇到** —— 一次性的修正不算；某個 API 的行為、某個插件的結構性問題才算
- **從程式碼和 git 看不出來** —— 已經寫在程式註解裡的不要再抄一份到 notes，那會變成
  兩份會漂移的真相

刻意排除：

- 逐條的變更清單（`git log` 已經有了）
- 「修好了 X」但沒說**為什麼會壞**、下次怎麼避免
- 只在當時那個對話有意義的來龍去脈

留意這幾種高價值訊號：

- 同一個症狀修了兩次以上 → 代表理解有誤，把正確的模型寫下來
- 錯誤訊息**沒有指向真正的原因** → 症狀到病因的對照表最值錢
- 「以為 A 結果是 B」的推翻 → 連同**是什麼證據推翻的**一起寫（下次才知道怎麼驗）
- 加了又移除的插件／做法 → 記下放棄的理由

### 3. 分流

| 性質 | 去處 |
|---|---|
| 規則、API 行為、某插件現況 | `.claude/notes/<name>.md` |
| 可重複執行的步驟 | `.claude/skills/<name>/SKILL.md` |
| 使用者的偏好與工作方式 | agent memory（不是 notes） |
| 驗證某件事的手法／巨集 | notes，並在相關技能裡指過去 |

判準：**要人照著操作的是技能，要人先知道的是筆記。**

### 4. 先更新，再新增

寫之前**一定要先讀** `.claude/notes/README.md` 的索引和既有檔案。同一主題已經有檔案就
改那一份，不要開新的 —— 這個目錄的價值來自「一個主題一個地方」。

新增檔案要同步更新 `.claude/notes/README.md` 的索引表。新增技能要確認 description 寫了
**觸發時機和中文關鍵字**，否則它不會被自動叫出來。

### 5. 同步 memory

`.claude/notes/` 是 agent memory 的匯出副本，**以 memory 為準**。所以順序是：先寫
memory，再匯出：

```bash
cp ~/.claude/projects/-Applications-World-of-Warcraft--ptr--Interface/memory/*.md .claude/notes/
rm .claude/notes/MEMORY.md
```

### 6. 回報

告訴使用者**寫了什麼、以及刻意沒寫什麼**。「這 40 個 commit 裡只有 3 件事值得留下」是
好結果，不是偷懶 —— 把 notes 灌水才是真的把它變沒用。
