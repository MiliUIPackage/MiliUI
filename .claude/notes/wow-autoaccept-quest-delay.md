**在 `QUEST_DETAIL` 裡直接呼叫 `AcceptQuest()` 會失敗**，而且失敗得很難認：
不報錯、伺服器不送任何訊息、任務視窗閃一下就關、任務沒進日誌。

**延後約 0.5 秒再按就穩定。**（2026-08-30 實測：0 / 0.25 秒失敗，0.5 / 1 / 3 秒成功。）

⚠ 但**不要對所有任務都延遲**，也**不要寫死秒數**。實作的形狀是：
預設秒接 → 按完查勤 → 沒進日誌就把那個 `questID` 記進**帳號層級**存檔、下次先等
0.5 秒 → 還是不行就每次加 0.1 秒（上限 2 秒）。
理由：週任的 questID 每週都不一樣（寫死清單隔週過期）、延遲量測值因人而異、
而絕大多數任務秒接完全沒問題。

## 病徵

同一條任務**第一次必定失敗、第二次必定成功**；放棄之後重演；手動點永遠第一次就成功
（因為人手移動滑鼠至少要一秒）。實測案例是週任「至暗之夜：阿塔烏特克寶庫」(98232)，
但成因跟任務本身無關。

## ⚠ 六個看起來很合理、但實測都錯的假設

會列出來是因為每一條我都真的走過一遍，總共花了七輪往返：

| 假設 | 被什麼打掉 |
|---|---|
| `QuestGetAutoAccept()` 殘留，害我們走 `CloseQuest()` | 旗標兩次都是 `false` |
| 對話／多選一的選取邏輯有問題 | 那條任務**完全沒有 `GOSSIP_SHOW`**，直接 `QUEST_DETAIL` |
| 我們搶在暴雪的 `QuestFrame` 前面，詳情頁還沒建好 | 兩次的 `QuestFrame:IsShown()` 與接受鈕的顯示／可按都是 `true`；延後一幀也沒改善 |
| 合成點擊 vs 硬體點擊（`btn:Click()` 不算數） | 等 3 秒之後我們自己按也會成功 |
| 獎勵資料還沒到齊 | 失敗與成功那兩次的 `GetNumQuestChoices` / `GetNumQuestRewards` / `GetQuestMoneyToGet` 完全一樣 |
| 任務資料非同步載入（`RequestLoadQuestByID` ＋ `QUEST_DATA_LOAD_RESULT`） | 那個事件在 **0.00 秒**就回 `success=true`，資料本來就在 |

**客戶端看得到的東西兩次完全一致，唯一能改變結果的是時間。** 也就是說有一個
**只有伺服器知道的暖機**，客戶端沒有任何訊號可以事先判斷 —— 所以只能延遲，
沒有「等訊號」的漂亮解法。

## 通則

- **狀態相同而結果不同 ⇒ 找時序，不要繼續找狀態。** 這一輪前三個假設都在找
  「哪裡不一樣」，而根本沒有不一樣。
- **排除一個方向之前，先確認自己的推論沒有踩到未驗證的前提。** 我一度用
  「第二次也只等一幀卻成功」排除掉「等太快」，那建立在「就緒窗口每次各自計算」
  這個從沒驗證過的假設上 —— 錯的，因此白繞了好幾輪。
- **要聽伺服器講話。** `UI_ERROR_MESSAGE` / `UI_INFO_MESSAGE` 應該一開始就掛上去，
  拒絕動作時它多半會直接說原因。（這次沒說，但那本身也是資訊。）
- **對照組要能區分變因。** 「關掉自動接、手動點」證明了是我們造成的；
  「開著自動接、拉長延遲、手動點」才證明了不是我們其他程式碼弄壞的。兩個都要做。
- **不要把少數任務的成本攤到全部任務上。** 一度改成「一律先等 0.5 秒」，看起來簡單，
  但練等時一路接幾十條任務、每條都慢半拍是看得出來的。正解是預設秒接、接不到才記起來。
- **量出來的常數不是普世常數。** 0.5 秒是在某一條連線上量的，別人的延遲不一樣，
  所以不能寫死 —— 要讓它每失敗一次加 0.1 秒，各自收斂到自己的值（上限 2 秒；
  加到上限還不行就代表成因不是等待時間，再加只是讓玩家更慢）。
- **查勤要查晚一點。** 按下去到 `QUEST_ACCEPTED` 之間可能接近一秒，太早查會把
  「還在路上」誤判成失敗、無謂地把等待往上加。查晚只影響「什麼時候學到」，
  不影響接任務本身，所以沒有理由省。

## 別的插件

同一個寫法（`QUEST_DETAIL` 進來直接 `AcceptQuest()`、零延遲）在
**EllesmereUI** 與 **Leatrix Plus** 都是這樣，兩支**都會中**。
**ElvUI 沒有自動接任務功能**（681 個 `.lua` 裡 `AcceptQuest` 出現 0 次，
跟 Quest 有關的檔案全在 `Skins/`），所以撞不到。

Reddit 與各開發者論壇搜不到討論 —— 合理，這個失敗不報錯也不留訊息，
看起來只像「偶爾沒接到」。

實作見 [[project-miliui-questtracker]] 的 `Modules/AutoQuest.lua`。
相關：[[wow-gettime-stamp-multipacket]]（同樣是「看起來是狀態、其實是時序」那一類）。
