`AddOns/MiliUI_BurstPotionHelper/` 是參考 `BurstPotionSwitcher` 重寫的爆發藥水切換插件（自製，已進 git 追蹤）。SavedVariables=`MiliUI_BurstPotionHelperDB`。

**核心設計（避免污染/秘密值）**：tainted Lua 在戰鬥中「零保護呼叫、零背包讀取」——`C_Item.GetItemCount`/`GetContainerItemInfo`/插件自己的 `SetAttribute` 只在非戰鬥執行（戰鬥中設 `pendingRebuild`/`pendingApply`，`PLAYER_REGEN_ENABLED` 補做）。秘密值只由 unit/aura 類 API 產生，此插件完全不碰。**插件完全不碰巨集**（不再有 `EditMacro`/`#showtooltip`/圖示同步——使用者要求移除，2026-06）。

**戰鬥中切換藥水/選擇不使用**：靠 SecureHandler 在受限環境內完成。每個切換列圖示是 `SecureActionButtonTemplate`，用 `SecureHandlerWrapScript(btn,"OnClick",btn,preBody)` 包一段 snippet：左鍵時把預存 `potionref`（非戰鬥寫入的 "bag slot"）複製到共用 use button（戰鬥合法）。`SecureHandlerSetFrameRef(btn,"use",useButton)`、wrap、`potionref` 全部只在非戰鬥寫。insecure `HookScript("OnClick")` 只在左鍵更新存檔/貼圖。

**右鍵直接喝（預設關，`db.rightClickUse`）**：開啟時 layout 給每個變體按鈕設 `type2="item"`/`item2=ref` → 右鍵直接喝該品質藥水（不影響選取）；none 鈕不設 type2。切換選項要重寫 type2（保護操作）→ `ns.SetRightClickUse` 非戰鬥才 relayout。

**點擊邊緣 gotcha（曾經喝不出來）**：(1) 巨集 `/click` 只送 up-edge，配 `ActionButtonUseKeyDown` cvar 開啟時普通 click action 不觸發 → use button 必須設 `pressAndHoldAction=true` + `typerelease`/`itemrelease`（外加 `type1`/`item1`），照抄 BurstPotionSwitcher 的配方。(2) selector 的 OnClick 被 `SecureHandlerWrapScript` 包過，`SafeCallWrappedHandler` 不轉傳 isSecureAction → 變 keypress(fire-on-down) → selector 要 `RegisterForClicks("AnyDown","AnyUp")` 兩邊都註冊才會剛好觸發一次；insecure hook 用 `if down then return end` 只在 up 跑一次。snippet 設 use button 時也要設整組（type/item/typerelease/itemrelease/type1/item1+pressAndHold），否則戰鬥中切換後 release 路徑會用到舊 ref。

**品質文字（最終版,信任偵測）**：使用者確認「自動偵測品質是對的」(之前覺得反了是還沒套用前的舊截圖)。所以 `ns.GetQualityLabel(itemID)` 對**所有**物品都用 `ns.GetItemQuality`(`C_TradeSkillUI.GetItemReagentQualityByItemInfo`,fallback 解析 `GetItemReagentQualityInfo().iconInventory` 的 `Tier(%d+)`)→ 這些藥水只有兩種品質,所以 `q>=2`→`LABEL_T3`高品質、`q==1`→`LABEL_T1`一般。`LABEL_T2`(中品質)目前用不到。**Data 已簡化成純 itemID 清單**(`ns.DEFAULT_ITEMS = {245897,245898,241308,...}` 照「每瓶:大鍋高/一般、工藝高/一般」順序,較小 ID 排前＝高品質在前),不再記 rank/kind/groupKey,移除了 `ns.POTIONS`/`VARIANT_BY_ID`/`GROUP_ORDER`/`GetVariantLabel`/`db.selectedKey`/「同群組優先選取」。`itemList`/`available` entry 只剩 `{id,isCustom,enabled}` 與 `{id,count,bag,slot}`。

**選擇持久化(2026-06 修過大坑,別回退)**:`db.selectedItemID` 是「使用者意圖」、**掃描永遠不可覆蓋它**。先前 `EnsureValidSelection` 寫成「選的那瓶不在 `byID` 就改成 `available[1]`」——但**登入時背包快取常是冷的**(掃到 0 瓶,跟 PositionBar 同一個冷快取事實),於是把存好的選擇洗成 nil→下次掃到變第一瓶,使用者回報「上線預設不是原本那罐」(間歇、偏向清單前段)。正解:`EnsureValidSelection` **只在 `selectedItemID==nil`(從沒選過)時**設初始預設,其餘一律不動;「現在實際要喝/標黃框的那瓶」改由 `GetSelected` **執行期計算**——存的那瓶在背包就用它、不在(冷快取/用完)就暫用 `available[1]` 當後備但**不寫回 DB**,等那瓶資料載好/補貨自動變回。三個呼叫處(`ApplySecure`、`Bar_UpdateSelection`、`Bar_Layout` 收合)都吃這個「有效選擇」、相容。`db.disabled`(不使用藥水)仍提前 return 保留。

**踩過的低級坑**：`db.itemEnabled[id] = enabled and nil or false` 在 Lua **永遠是 false**(`X and nil` 短路成 nil 再 `or false`)→勾選永遠停用、無法再勾。正解用 `if enabled then nil else false`。`RestoreDefaults` 要同時 wipe `removedDefaults` ＋清掉 default 的 `itemEnabled`(重新啟用),否則「恢復預設」對被停用的沒作用。**清單高度/捲軸(踩過坑)**:canvas 子面板 frame 比「可見視窗」高,**別把 `scrollArea` 底部錨到 `listPanel`**(會爆出視窗外、捲軸不出現)。正解 `FitScrollArea`:`scrollArea` 固定寬(`LIST_WIDTH`)、高度 = `scrollArea:GetTop() - SettingsPanel:GetBottom() - 44`(夾 140~1000,算不出就退 `LIST_HEIGHT`);maxScroll 用 `scrollArea:GetHeight()`。geometry 在 OnShow 當下還沒解析→**別用 `C_Timer.After` 硬撐**,改掛 `listPanel:OnSizeChanged`(Settings 真正調整 canvas 尺寸時才觸發)重算。**`OnSizeChanged` 只呼叫輕量 `UpdateListScroll`(=`FitScrollArea`＋用快取 `listContentH` 重算捲軸),不重建列、不重配 closure**——`RefreshSettingsList`(整份重建)只留給 OnShow/清單變更/item 載入。(`SettingsPanel` XML 雖標 `resizable="true"` 但固定 920×724、無 resize 把手,實際拖不動,所以 OnSizeChanged 不會狂發;拆分主要是避免「改尺寸卻整份重建」的浪費＋未來防呆。)**最大的坑**:Settings **canvas 面板在自己的 OnShow 期間 `IsShown()` 會回 false**,所以 `RefreshSettingsList` **絕對不能加 `if not listPanel:IsShown() then return end`**(會整個清單空白)——仿 BloodlustMusic 一律無條件重建。先前清單能顯示是靠常駐 `ITEM_DATA_LOAD_RESULT` 在稍後(IsShown 才變 true 時)補叫,把那事件改面板區域註冊後就暴露了這個 guard 的 bug。**第二層坑(要多點幾次才出現)**:即使拿掉 guard,Settings canvas **不會 render「在它第一次 OnShow 期間才被 `CreateFrame` 建立的子框架」**——所以列要點好幾次才冒出來。解法照 BloodlustMusic:**預先建好列框架**——在 `PLAYER_LOGIN`(此時 DB 已載入,不必像 BLM 用 `C_Timer`)呼叫一次 `ns.RefreshSettingsList()`,讓 row 框架在首次 OnShow 之前就存在;OnShow 只是重用＋顯示既有框架(已建好的框架顯示沒問題)。另比照 BLM `ForceShowTrackList`,在建列迴圈內對 `row.check/icon/name/del` 補 `:Show()`。**第三層坑(2026-08 修)**:「打開設定時勾選框全部沒勾」——面板是 `UIParent` 子框、建立當下就 shown,從**別的 canvas 面板**切進來時 `frame:Show()` 是 no-op → OnShow 整個不觸發,勾選框停在建立時的未勾狀態,而且此時去點會把錯值寫回 DB。正解:兩個面板註冊前先 `:Hide()`,並把 DB→UI 的刷新掛在 `panel.OnRefresh`(Blizzard 每次顯示必呼叫,原本被寫成空函式浪費掉),OnShow 留作第二條路徑;`ns.GetDB()` 也加了「global 被換掉就重新 InitDB」的防呆。詳見 [[wow-settings-canvas-onrefresh]]。

**品質星徽圖標**：別用 rank 猜 tier（會錯，尤其大鍋）。用 Blizzard 在背包按鈕的同一來源 `C_TradeSkillUI.GetItemReagentQualityInfo(itemID).iconInventory` 取 atlas（保證和遊戲內一致），再用 `C_Texture.GetAtlasInfo` 拿原生尺寸 ×`BADGE_SCALE`(=1，原生大小) 顯示。沒品質的物品回 nil → 不顯示徽章。

**「不使用藥水」按鈕**：切換列尾端固定一顆紅色禁止圖示（`Interface\RaidFrame\ReadyCheck-NotReady`），potionref="" → snippet 清空 use button；選中一樣套黃框（`db.disabled` 旗標）。X 圖透明，所以 `slotBg`（不透明近黑、內縮 1px）要畫在黃 `border` 之上（sublevel 2 > border 1），選中時只露出 2~3px 黃框、底維持黑色（否則整格變黃）。

**語系架構**：用 AceLocale-3.0（`Libs/LibStub`+`Libs/AceLocale-3.0`、`embeds.xml`、`Locales/Locales.xml` 載 `enUS/zhTW/zhCN.lua`），仿 MiliUI_BloodlustMusic。enUS 為 default(`NewLocale(...,true)`)、其餘 `NewLocale(...,locale); if not L then return end`。Core.lua 頂 `ns.L = LibStub("AceLocale-3.0"):GetLocale(addonName)`（TOC 要先載 embeds+Locales 再載 Core）。新增字串記得三個語系檔都加（enUS 必加否則 AceLocale 報錯）。

**藥水冷卻顯示（`db.showCooldown`，預設開）**：每個 selector 加一個 `CooldownFrameTemplate` 子框（insecure，不繼承保護→戰鬥中更新安全）。`ns.Bar_UpdateCooldowns` 用 `C_Item.GetItemCooldown(itemID)`→`CooldownFrame_Set` 套用；由 `BAG_UPDATE_COOLDOWN` 事件（戰鬥中也照跑）+ `Bar_Refresh` 末尾 + 選項切換觸發。count/badge 移到一個比 cooldown 高 5 級的 overlay 子框，CD 轉圈時數字仍可讀。none 鈕無 itemID→不顯示 CD。

**收合（`db.collapsed`）**：左鍵點拖曳把手 grip 收合成只剩選取那一格／再點還原。grip 用 `_moved` 旗標分辨「拖動(移動)」vs「點擊(收合)」：OnMouseDown 重置 `_moved=false`、OnDragStart 設 true、OnMouseUp 左鍵且 `not _moved` 才 toggle。收合要 Hide 受保護的 selector → 戰鬥中不能做，`Bar_ToggleCollapse` 戰鬥中改設 `pendingApply` 出戰再套，並印 `MSG_COLLAPSE_COMBAT` 提示。**（2026-06 實測確認：戰鬥中強制 relayout 會噴一連串 `ADDON_ACTION_BLOCKED`——`SetAttribute`/`Show`/`ClearAllPoints`/`SetPoint`/`SetWidth`/`SetShown`，連 `MiliUI_BurstPotionHelperBar` frame 本身都被擋。所以收合/展開在戰鬥中絕對只能延後，別再試著放行。）**`Bar_Refresh` 收合時只把「選取那格(或 disabled 時的 none 鈕)」放進 `cells` 重新 pack。**收合靠左 + 預設位置**：列一律用 `BOTTOMLEFT`→UIParent `BOTTOMLEFT` 錨點（`db.bar={x,y,v}` 存左下角絕對座標），所以任何寬度變化都往右伸縮、左緣固定。`db.bar.x/y=nil` 代表「自動擺放一次」：`PositionBar`（要等掃到藥水 `#available>0` 才算）x=`(螢幕寬-ExpandedWidth)/2` 置中、y=`UIParent:GetHeight()*DEFAULT_Y_FRACTION`(0.10，螢幕下方約10%＝動作條上方，解析度無關)。**注意：`PositionBar()` 必須在 `Bar_Refresh` 末尾呼叫**（不能只在 PLAYER_LOGIN）——登入時背包快取可能是冷的、掃到 0 瓶 → 會跳過定位、列卡左邊 x=0；要等 BAG_UPDATE 掃到藥水那次 Bar_Refresh 才定位。拖曳 `SavePosition` 用 `GetLeft/GetBottom` 實際幾何存檔再重錨。**位置版本** `ns.BAR_POS_VERSION`：改預設位置時 +1；InitDB 偵測舊格式(`db.bar.point`)或 `db.bar.v` 不符 → 重設 `{x=nil,y=nil,v=新版}` 一次性重新擺放（之後拖曳會保留，因 SavePosition 不動 v）。（先前 `PinLeft` 偏移換算法不可靠已移除。）grip tooltip：鎖定時顯示「已鎖定」否則「拖動以移動」，外加「左鍵：收合／展開」「右鍵開啟設定」。藥水格 tooltip 只剩「左鍵：選擇此藥水」(＋勾右鍵時「右鍵：直接使用此藥水」)，none 鈕「左鍵：不使用藥水」。

**效能模型（2026-06 已最佳化,別回退）**：全插件**零 `OnUpdate` 輪詢**,純事件驅動;框架池化重用(`ns.buttons[]`/設定列 `rows[]`)。四項最佳化已實作:(1)`ScanAvailable` 用 `BuildBagSlotMap` **單次走訪背包**(`[itemID]={bag,slot}`,照 `BAG_INDICES` 順序取第一個 stackCount>0,等價舊 `FindBagSlot` 首個命中)取代「每瓶各走一遍背包」的 O(瓶×格);count 仍用 `GetItemCount`(語意不變)。`FindBagSlot` 保留作 `GetItemRef` 的後備。(2)`ns.GetItemQuality`(Core)與 `GetQualityAtlas`(Bar)**memoize**——品質/atlas 每個 itemID 恆定,只快取非 nil 結果(未載入的下次重試)。(3)`ITEM_DATA_LOAD_RESULT` 是全域高頻事件,**改成只在設定清單面板 `OnShow` 註冊、`OnHide` 取消**(Core 不再常駐註冊),平時遊戲完全不進 handler。(4)`bags` 表提成模組常數 `BAG_INDICES`(免每次 new);`Bar_UpdateCooldowns` 在 `showCooldown=false` 時用 `ns.cooldownsShown` 旗標「清一次後就 return」(swirl 只在 show=true 分支設,故安全)。

**機制**：單一隱藏 `SecureActionButton`（global 名 `MiliUIBurstButton`），巨集 `ns.MACRO_LINE = "/click MiliUIBurstButton"`（使用者要求拿掉 LeftButton；`/click` 預設就是左鍵，功能不變）。grip 把手是方向三角形（`ChatFrameExpandArrow` 貼圖＋vertexcolor 暗灰藍）：收合顯示▶(右,texcoord 0,1,0,1)、展開顯示◀(左,水平翻轉 1,0,0,1)，由 `ns.Bar_UpdateGripArrow`（Bar_Refresh 末尾＋CreateBar）依 `db.collapsed` 更新。框架用 MiliUI 無邊框風格（`WHITE8X8` edge `edgeSize=1` + 暗底，參 `MiliUI/Style.lua`）。設定面板用原生 `Settings` canvas，只留「切換時聊天提示」+ 顯示/鎖定列 + 右鍵直接喝 + 複製巨集 popup + 重置位置。

**可編輯藥水清單（item 級，仿 BloodlustMusic）**：設定面板有子分頁「藥水清單」(`Settings.RegisterCanvasLayoutSubcategory`)，每個 itemID 一行(勾選啟用＋刪除X)，可手動新增(輸入 ID 或 Shift 點物品連結，靠 `hooksecurefunc("HandleModifiedItemClick")` 帶入)。**資料模型**：預設清單放程式碼 `ns.DEFAULT_ITEMS`(由 `ns.POTIONS` 攤平)＋`ns.DEFAULT_ITEM_SET`；DB 只存 `db.itemEnabled[id]=false`(停用)、`db.removedDefaults[id]=true`(刪掉的預設)、`db.customItems[]`(自訂)。`ns.RebuildItemList()` 合併「預設(未刪)＋自訂」成 `ns.itemList`,`ScanAvailable` 只掃啟用的。**改版自動帶新預設**:因為預設來自程式碼,我在 Data.lua 加新水→所有人自動出現(新 key 不在 removedDefaults→預設啟用),不用遷移;季更新換 itemID 也自動套用。操作:`ns.SetItemEnabled/RemoveItem/AddItem/RestoreDefaults`→`RefreshFromListChange`(戰鬥中設 pendingRebuild,清單 UI 用 `ns.RefreshSettingsList` 即時重畫,因 RebuildItemList 是純 DB 讀取、戰鬥安全)。`bar` 的 available entry 現在是 `{id,groupKey,count,bag,slot}`(不再有 .potion/.variant)。

**分環境記憶（`db.splitByContext`，預設開，2026-07）**：選擇（`selectedItemID`/`disabled`）依環境分開存 `db.profiles[ctx]`，六個 ctx：world／party（M+/五人地城）／raid／pvp（戰場）／arena／scenario（探究/儀式）。**環境判斷**（`ns.ComputeContext`，掛 `PLAYER_ENTERING_WORLD`）：`GetInstanceInfo` 的 instanceType 為主，但 **"party" 不可直接信**——要塞/跟隨者地城(205)/任務副本(216)也回 "party"，須再過 difficultyID 白名單 {1,2,8(M+),23,24}（用 `DifficultyUtil.ID` 常數+數字 fallback）；`scenario` 概括探究(208)與 Midnight 儀式地點（無專屬 ID 記載，用 instanceType 免追新 ID）；其餘歸 world。**存取一律走 `ns.SelStore()`**（split 關閉時回傳 db 本體；profile 懶建立、以共用欄位為種子），`OnSelect/OnSelectNone` 同時鏡寫共用欄位（關閉選項時保留最後選擇）。UI：設定面板頂部 `SETTINGS_CURRENT_CONTEXT` 顯示目前記憶（OnShow 才更新——BuildPanel 在檔案載入期執行，**不可在 build 時讀 DB**，SavedVariables 未載入）；grip tooltip 加 `TIP_CONTEXT`；換環境時聊天印 `MSG_CONTEXT_APPLIED`。

**每季維護**：`Data.lua` 的藥水 itemID 是當季資料：圣光潜力(241308/241309, 大鍋245898/245897)、鲁莽(241288/241289, 大鍋245903/245902)、惡念狂飲 Draught of Rampant Abandon(241292/241293, 大鍋245911/245910)。改版換新藥水要更新（類似 [[project-itemupgrade-preview-icon]] 的季更新模式）。toc 版本號跟 [[project-toc-interface-bump]] 一起 bump。
